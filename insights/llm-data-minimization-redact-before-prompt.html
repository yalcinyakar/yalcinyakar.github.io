Data Minimization for LLM Applications: Redact Before You Prompt

The safest sensitive field is the one that never enters the model request. Build the smallest task payload first, then redact, verify and log only what the workflow actually needs.

LLM integrations often begin with a convenient object: a support ticket, customer record, incident payload, document or conversation. Passing that object directly to a model is easy. It also turns every attached field into part of the application’s AI data flow, whether the task needs it or not.

A summarization request may need the issue text and product category, but not a full name, email address, authentication token, internal note or raw account identifier. Asking the model to “ignore sensitive data” does not remove that data from the request. Minimization must happen in deterministic application code before prompt assembly.

Start with purpose, not available fields

Define the decision the model supports and list the minimum information required for that decision. Use a field allowlist rather than a denylist. A denylist tries to predict every sensitive field name; an allowlist makes new fields excluded by default.

NIST’s AI Risk Management Framework treats privacy as part of trustworthy AI, and the framework notes that data-minimizing methods such as de-identification and aggregation can support privacy-enhanced systems. Its Generative AI Profile extends risk management across the GAI lifecycle rather than treating privacy as a final prompt instruction.

For each permitted field, decide whether the model needs the original value, a generalized value, a pseudonymous reference, or no value. A delivery city may be sufficient where a street address is not. An account tier may be useful where an account number is not. A stable pseudonym can support correlation without exposing the source identifier.

Build a pre-prompt trust boundary

Place minimization between authorized data retrieval and prompt construction. The sequence should be explicit:

  1. authorize the caller and retrieve only permitted records;
  2. project the record through a task-specific field allowlist;
  3. redact sensitive patterns inside permitted free text;
  4. replace identifiers with scoped pseudonyms when correlation is required;
  5. verify that prohibited patterns are absent before sending;
  6. apply output validation before displaying or acting on the response.

OWASP’s Sensitive Information Disclosure guidance recommends sanitization, input validation, restricted data sources and least-privilege access. It also warns that prompt instructions about confidentiality may not always be followed. The enforcement point therefore belongs outside the model.

A runnable minimization gate

This dependency-free Python example creates a minimal payload for a synthetic support-summary task. It allowlists three source fields, masks email addresses and token-like strings inside free text, and converts the account ID into a scoped HMAC reference.

import hashlib
import hmac
import json
import re

# Demonstration key only. Load a real key from managed secret storage.
DEMO_KEY = b"demo-key-not-for-production"
EMAIL = re.compile(r"\b[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,}\b", re.I)
TOKEN = re.compile(r"\b(?:sk|api|token)[-_][A-Z0-9_-]{8,}\b", re.I)

def pseudonymize(value, scope):
    message = f"{scope}:{value}".encode()
    return hmac.new(DEMO_KEY, message, hashlib.sha256).hexdigest()[:12]

def redact(text):
    text = EMAIL.sub("[EMAIL]", text)
    return TOKEN.sub("[TOKEN]", text)

def build_payload(record):
    # Explicit projection: name, email, api_key and notes never enter payload.
    payload = {
        "locale": record["locale"],
        "account_ref": pseudonymize(record["account_id"], "support-summary"),
        "issue": redact(record["issue"]),
    }
    encoded = json.dumps(payload, sort_keys=True)
    if EMAIL.search(encoded) or TOKEN.search(encoded):
        raise ValueError("Sensitive pattern survived minimization")
    return payload

source = {
    "name": "Example User",
    "email": "person@example.test",
    "account_id": "ACC-0042",
    "locale": "en",
    "issue": "Contact person@example.test; token-ABCD1234 must be rotated.",
    "api_key": "api-NEVER_SEND99",
    "internal_notes": "Synthetic note that the model does not need.",
}

safe = build_payload(source)
print(json.dumps(safe, indent=2, sort_keys=True))
rendered = json.dumps(safe)
assert "Example User" not in rendered
assert "person@example.test" not in rendered
assert "NEVER_SEND" not in rendered
assert safe["issue"] == "Contact [EMAIL]; [TOKEN] must be rotated."

Save it as minimize_payload.py and run python3 minimize_payload.py. The output contains the locale, a scoped reference and redacted issue text—nothing else from the source object.

The regexes are deliberately small and are not a complete DLP system. Real deployments need detectors appropriate to their languages, identifiers and data classes, plus tests for obfuscation, Unicode variants, encoded values and false positives. HMAC keys belong in managed secret storage and should be rotated under a defined policy.

Provider controls are not minimization

Transport encryption, training policies, regional processing and retention settings matter, but they answer different questions. OpenAI’s current data controls documentation, for example, distinguishes abuse-monitoring logs from application state and documents endpoint-specific retention behavior. An integration should verify the settings for the exact endpoint and features it uses.

Those controls do not make unnecessary input necessary. Data that is removed before the request cannot appear in provider logs, traces, prompt caches, model output or downstream debugging artifacts. Minimize first; then configure provider and infrastructure controls for the smaller remaining payload.

Test the negative space

Most tests confirm that required fields are present. Privacy tests must also confirm that prohibited fields are absent. Create synthetic fixtures containing every sensitive class, run them through the full prompt builder, and fail if raw values survive. Test both request and response paths, because the model may reproduce sensitive context it legitimately received.

Keep prompt composition observable without logging raw prompts by default. Record the minimizer version, policy ID, allowed field names, detector results and payload hash. Apply the same discipline to retrieved documents using the task-focused selection approach in context engineering for AI coding assistants. For RAG, enforce authorization before retrieval and measure retrieval independently as described in RAG evaluation.

Finally, treat model output as untrusted. Parsing and schema checks are only the beginning; apply the business validation described in LLM output validation beyond valid JSON. If the system proposes an external action, bind authorization to the exact minimized and validated proposal using a real human approval gate.

Responsible AI integration starts before inference. The model should receive enough information to perform one bounded task—not every field the application happened to retrieve.

Primary sources checked November 6, 2026. All records and identifiers in the example are synthetic and report no personal production results.
