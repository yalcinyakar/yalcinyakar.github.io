Prompt Caching for Generative AI: Design Stable Prefixes, Then Measure

Prompt caching is not a switch that makes every repeated request cheaper. It is a request-design problem: keep reusable context stable, isolate changing input and verify the result with usage data.

Generative AI applications often resend the same material: developer instructions, output schemas, tool definitions, examples, policies or a long reference document. Reprocessing that shared context on every request adds latency and input cost even though most of the prompt has not changed. Prompt caching lets a provider reuse previously computed state for an identical prompt prefix.

The important word is prefix. A cache does not search the request for vaguely similar paragraphs. It matches reusable content from the beginning up to an eligible boundary. A timestamp near the top, reordered tools or a regenerated schema can turn a seemingly identical request into a cache miss.

Build the request in two zones

Separate each request into a stable prefix and a dynamic suffix. The prefix should contain content reused across a meaningful group of calls:

  • developer instructions and policy constraints;
  • tool definitions in a deterministic order;
  • output schemas serialized consistently;
  • few-shot examples that belong to the application version;
  • shared reference material.

The suffix contains values expected to change: the current user message, request identifiers, timestamps, retrieved records and per-call configuration. Keep those values after the reusable boundary.

OpenAI’s prompt-caching guide recommends stable instructions and reference material first, with dynamic content later. Anthropic’s prompt-caching documentation similarly describes caching the full prompt prefix through a breakpoint. Google’s Gemini context-caching guide advises placing large common content at the beginning to improve implicit cache-hit probability. The APIs differ, but the architectural rule is consistent.

Stability means bytes, not intent

Two schemas may be semantically equivalent while their serialized text differs. Key ordering, whitespace, generated descriptions or version banners can change the rendered prefix. Tool arrays are especially easy to destabilize if they are built from an unordered collection.

Use deterministic serialization and explicit versioning. Sort keys, preserve array order, normalize line endings and keep application metadata outside the prefix unless it genuinely affects model behavior. When a policy or tool changes, increment a prefix version deliberately. That turns an unexplained miss into an observable deployment event.

A runnable prefix audit

The following dependency-free Python script does not imitate a provider cache. It verifies the property a cache needs: identical reusable prefixes produce identical fingerprints, while per-request values remain outside that fingerprint.

import hashlib
import json

TOOLS = [
    {"name": "lookup_order", "schema": {"type": "object",
      "properties": {"order_id": {"type": "string"}},
      "required": ["order_id"]}},
    {"name": "create_summary", "schema": {"type": "object",
      "properties": {"text": {"type": "string"}},
      "required": ["text"]}},
]

def canonical(value):
    return json.dumps(value, sort_keys=True, separators=(",", ":"))

def build_request(user_text, request_id):
    stable_prefix = {
        "prefix_version": "support-v3",
        "developer": "Answer from supplied context. Never invent records.",
        "tools": TOOLS,
        "output_schema": {
            "type": "object",
            "properties": {"answer": {"type": "string"}},
            "required": ["answer"],
        },
    }
    dynamic_suffix = {
        "request_id": request_id,
        "user": user_text,
    }
    fingerprint = hashlib.sha256(
        canonical(stable_prefix).encode("utf-8")
    ).hexdigest()[:16]
    return stable_prefix, dynamic_suffix, fingerprint

first = build_request("Summarize order A-17", "req-1001")
second = build_request("Summarize order B-42", "req-1002")

assert first[2] == second[2]
assert first[1] != second[1]
print("stable_prefix_sha256:", first[2])
print("dynamic_request:", canonical(second[1]))

Save the file as prefix_audit.py and run python3 prefix_audit.py. Add this fingerprint to structured application telemetry, not to the model prompt. If the fingerprint changes unexpectedly between requests that should share a prefix, inspect the request builder before blaming provider routing.

Do not optimize only for hit rate

A high cache-hit rate can still hide a poor design. Padding a prefix with irrelevant material may cross a provider’s cache eligibility threshold while increasing uncached input, cache writes and model distraction. Cache only context the task needs.

Track at least five values by model and prefix version: total input tokens, cached input tokens, cache-write tokens where exposed, time to first token and realized input cost. Compare warm and cold requests separately. OpenAI exposes cached-token and cache-write details in usage data; Anthropic reports cache-read and cache-creation input tokens; Gemini returns cached-token information in usage metadata. Field names and pricing change, so read the current provider documentation rather than hard-coding assumptions into dashboards.

Roll out caching behind a configuration flag, collect a cold baseline, then compare several warm repetitions with the same prefix. A single successful hit proves eligibility; a distribution reveals whether the design remains effective under normal traffic.

Use a small evaluation set before and after restructuring. Moving instructions changes prompt layout even when wording remains the same. Verify task success, formatting and safety behavior, following the paired-case discipline described in LLM evaluation with uncertainty.

Cache boundaries are also data boundaries

Reusable does not mean universally shareable. Tenant-specific policies, private documents and user history should not be placed in a global prefix merely to improve reuse. Group cacheable context at the narrowest valid scope and follow the provider’s isolation controls. Remove unnecessary sensitive fields before prompt construction using the approach in data minimization for LLM applications.

Prompt caching works best when request construction is boring: stable instructions first, deterministic tools and schemas, dynamic input last, deliberate version changes and measured outcomes. That discipline improves more than cache reuse. It makes prompts easier to diff, test and operate as production software.
